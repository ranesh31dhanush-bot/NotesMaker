**Rapid Revision Sheet (10 minutes)**

**Event Loop Phases (Node.js)**

1. **Timers**: setTimeout, setInterval
2. **Pending Callbacks**: I/O callbacks (e.g., TCP, file system)
3. **Idle/Prepare**: internal use only
4. **Poll**: I/O callbacks (e.g., file read, DB response)
5. **Check**: setImmediate callbacks
6. **Close Callbacks**: socket.on('close', ...), cleanup events

**Memory Trick**: "Timers Pending Idle Poll Check Close" (TPICPC)

**Key Points**

* Poll phase controls flow
* setTimeout does NOT guarantee exact timing
* setImmediate runs before setTimeout (inside I/O)

**Call Stack vs Callback Queue vs Microtask Queue**

1. **Call Stack**: execution engine (LIFO)
2. **Callback Queue**: setTimeout, setInterval, I/O callbacks
3. **Microtask Queue**: Promise.then(), Promise.catch(), queueMicrotask()

**Priority Order**

1. Call Stack
2. process.nextTick() (Node.js special)
3. Microtask Queue (Promises)
4. Callback Queue (Timers, I/O)

**Golden Rules**

1. If stack is not empty, NOTHING runs
2. After stack empty, run ALL microtasks
3. Then, take ONE callback from callback queue

**Mental Model**

Imagine a chef cooking (Call Stack), handling VIP orders (Microtasks), and then normal orders (Callback Queue)

**Example Outputs**

* `setTimeout` vs `setImmediate` (order may vary)
* `Promise.resolve().then()` vs `setTimeout` (Promise runs first)
