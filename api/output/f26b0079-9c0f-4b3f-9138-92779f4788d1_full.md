**Event Loop Phases and Call Stack vs Callback Queue vs Microtask Queue**
====================================================================================

### Event Loop Phases

The event loop is the core of Node.js, allowing it to handle multiple operations without blocking. It runs in phases, each with its own type of tasks.

#### Phases of the Event Loop

1. **Timers**: Callbacks scheduled by `setTimeout()` and `setInterval()`.
2. **Pending Callbacks (I/O callbacks)**: System-level callbacks and errors from TCP, file system, etc.
3. **Idle/Prepare**: Internal phase used by Node.js.
4. **Poll Phase (MOST IMPORTANT)**: Executes I/O callbacks, waits for new I/O events, and decides whether to wait or move to the next phase.
5. **Check Phase**: `setImmediate()` callbacks.
6. **Close Callbacks**: Socket close events and cleanup events.

#### Example

```javascript
console.log("Start");

setTimeout(() => {
  console.log("Timer");
}, 0);

setImmediate(() => {
  console.log("Immediate");
});

fs.readFile(__filename, () => {
  console.log("File Read");
});

console.log("End");
```

Possible output:
```
Start
End
Timer / Immediate (order may vary!)
File Read
```

### Call Stack vs Callback Queue vs Microtask Queue

#### Call Stack (Execution Engine)

* A stack (LIFO) where functions are executed.
* JavaScript is single-threaded, so only one thing runs at a time.

Example:
```javascript
function a() {
  console.log("A");
}

function b() {
  a();
  console.log("B");
}

b();
```

Execution:
```
Call Stack:
b()
  → a()
       → console.log("A")
  → console.log("B")
```

Output:
```
A
B
```

#### Callback Queue (Macrotask Queue)

* Stores `setTimeout`, `setInterval`, I/O callbacks, and `setImmediate`.
* Async task finishes, its callback goes into the callback queue.
* Event loop waits for the call stack to be empty, then pushes it to the stack.

Example:
```javascript
setTimeout(() => {
  console.log("Timer");
}, 0);

console.log("Hello");
```

Flow:
```
Call Stack → console.log("Hello") → done
Timer finishes → goes to Callback Queue
Event Loop → moves it to Call Stack
```

Output:
```
Hello
Timer
```

#### Microtask Queue (HIGH PRIORITY)

* Stores `Promise.then()`, `Promise.catch()`, `queueMicrotask()`, and `process.nextTick()` (Node.js special).
* Microtasks run BEFORE the callback queue.
* They run IMMEDIATELY after the current stack is empty.

Example:
```javascript
setTimeout(() => console.log("Timer"), 0);

Promise.resolve().then(() => {
  console.log("Promise");
});

console.log("End");
```

Output:
```
End
Promise
Timer
```

### Priority Order

1. Call Stack
2. `process.nextTick()`
3. Microtask Queue (Promises)
4. Callback Queue (Timers, I/O)

### Golden Rules

1. If the stack is not empty, NOTHING runs.
2. After the stack is empty, run ALL microtasks.
3. Then, take ONE callback from the callback queue.

### Real-World Analogy

Think of:

* Call Stack → Chef cooking
* Microtasks → Urgent VIP orders
* Callback Queue → Normal orders

The chef finishes the current dish, immediately handles VIP orders, and then goes to the normal queue.

### Summary

* Call Stack = where code runs
* Microtask Queue = high priority async (Promises)
* Callback Queue = lower priority async (Timers, I/O)
* `process.nextTick()` = highest priority in Node.js
