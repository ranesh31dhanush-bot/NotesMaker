**Event Loop Phases and Asynchronous Execution in Node.js**
===========================================================

### Introduction to Event Loop Phases

The event loop is the core of Node.js, allowing it to handle multiple operations without blocking, despite running on a single thread. It can be thought of as a factory worker checking different sections in a fixed order. The event loop runs in phases, each with its own type of tasks.

#### Phases of the Event Loop

1. **Timers**: Callbacks scheduled by `setTimeout()` and `setInterval()` are executed here.
2. **Pending Callbacks (I/O callbacks)**: System-level callbacks, such as errors from TCP or the file system, are handled here.
3. **Idle/Prepare**: This phase is used internally by Node.js and is not directly interacted with.
4. **Poll (MOST IMPORTANT)**: This is the heart of the event loop, where I/O callbacks (like file reads or database responses) are executed, and the event loop waits for new I/O events.
5. **Check**: `setImmediate()` callbacks are executed here.
6. **Close Callbacks**: Socket close events and other cleanup events are handled here.

### Example of Event Loop Phases

```javascript
const fs = require("fs");

console.log("Start");

setTimeout(() => {
  console.log("Timer");
}, 0);

setImmediate(() => {
  console.log("Immediate");
});

fs.readFile(__filename, () => {
  console.log("File Read");
});

console.log("End");
```

Possible output:
```
Start
End
Timer / Immediate (order may vary!)
File Read
```

### Understanding `setTimeout` vs `setImmediate`

The order of execution between `setTimeout` and `setImmediate` can vary depending on whether they are inside an I/O operation or not.

```javascript
const fs = require("fs");

fs.readFile(__filename, () => {
  setTimeout(() => console.log("Timer"), 0);
  setImmediate(() => console.log("Immediate"));
});
```

Output:
```
Immediate
Timer
```

### Call Stack, Callback Queue, and Microtask Queue

#### Call Stack (Execution Engine)

* A stack (LIFO) where functions are executed.
* JavaScript is single-threaded, so only one thing runs at a time.

Example:
```javascript
function a() {
  console.log("A");
}

function b() {
  a();
  console.log("B");
}

b();
```

Output:
```
A
B
```

#### Callback Queue (Macrotask Queue)

* Stores `setTimeout`, `setInterval`, I/O callbacks, and `setImmediate` callbacks.
* Async tasks finish and their callbacks go into the callback queue.
* The event loop waits for the call stack to be empty and then pushes the callback to the stack.

Example:
```javascript
setTimeout(() => {
  console.log("Timer");
}, 0);

console.log("Hello");
```

Output:
```
Hello
Timer
```

#### Microtask Queue (HIGH PRIORITY)

* Stores `Promise.then()`, `Promise.catch()`, `queueMicrotask()`, and `process.nextTick()` (Node.js special).
* Microtasks run before the callback queue and immediately after the current stack is empty.

Example:
```javascript
setTimeout(() => console.log("Timer"), 0);

Promise.resolve().then(() => {
  console.log("Promise");
});

console.log("End");
```

Output:
```
End
Promise
Timer
```

### Priority Order

1. Call Stack
2. `process.nextTick()` (Node.js special)
3. Microtask Queue (Promises)
4. Callback Queue (Timers, I/O)

### Golden Rules

* If the stack is not empty, nothing runs.
* After the stack is empty, run all microtasks.
* Then, take one callback from the callback queue.

### Real-World Analogy

Think of:

* Call Stack → Chef cooking
* Microtasks → Urgent VIP orders
* Callback Queue → Normal orders

The chef finishes the current dish, immediately handles VIP orders, and then goes to the normal queue.

### Summary

* Call Stack = where code runs
* Microtask Queue = high priority async (Promises)
* Callback Queue = lower priority async (Timers, I/O)
* `process.nextTick()` = highest priority in Node.js
